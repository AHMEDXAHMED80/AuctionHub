Stripe Payment Integration Plan for Wallet Top-up
====================================================

PROJECT OVERVIEW:
-----------------
This plan integrates Stripe payment processing to allow users to top up their 
wallet balance using credit/debit cards (Visa, MasterCard, etc.). The existing 
Payment and Wallet entities will be used to track transactions.


PHASE 1: BACKEND SETUP
-----------------------

1. **Add Stripe Java SDK Dependency**
   Location: pom.xml
   
   Add the official Stripe Java SDK:
   ```xml
   <dependency>
     <groupId>com.stripe</groupId>
     <artifactId>stripe-java</artifactId>
     <version>26.13.0</version>
   </dependency>
   ```
   Note: Using latest stable version (as of Jan 2026). Check https://github.com/stripe/stripe-java for updates.

2. **Stripe Configuration**
   Location: src/main/resources/application.properties
   
   Add Stripe API keys (use environment variables in production):
   ```properties
   # Stripe Configuration
   stripe.api.key=${STRIPE_SECRET_KEY:sk_test_your_test_key_here}
   stripe.webhook.secret=${STRIPE_WEBHOOK_SECRET:whsec_your_webhook_secret}
   stripe.currency=usd
   ```
   
   IMPORTANT: 
   - Never commit real API keys to version control
   - For production, use environment variables
   - Get keys from: https://dashboard.stripe.com/apikeys
   - Webhook secret comes from: https://dashboard.stripe.com/webhooks

3. **Create StripeService**
   Location: src/main/java/com/example/auctionhub/auctionhub/service/StripeService.java
   
   Responsibilities:
   - Initialize Stripe with API key
   - Create PaymentIntent for wallet top-up
   - Verify webhook signatures
   - Handle webhook events
   
   Key Methods:
   ```java
   - PaymentIntent createPaymentIntent(BigDecimal amount, Long userId)
   - Event constructWebhookEvent(String payload, String sigHeader)
   - void handlePaymentIntentSucceeded(PaymentIntent paymentIntent)
   - void handlePaymentIntentFailed(PaymentIntent paymentIntent)
   ```

4. **Create PaymentService**
   Location: src/main/java/com/example/auctionhub/auctionhub/service/PaymentService.java
   
   Responsibilities:
   - Create and save Payment records in database
   - Update payment status based on webhook events
   - Link payments to users and wallets
   
   Key Methods:
   ```java
   - Payment createPaymentRecord(User user, BigDecimal amount, String paymentIntentId, String clientSecret)
   - Payment updatePaymentStatus(String paymentIntentId, PaymentStatus status, String failureReason)
   - Payment findByStripePaymentIntentId(String paymentIntentId)
   ```

5. **Update WalletService**
   Location: src/main/java/com/example/auctionhub/auctionhub/service/WalletService.java
   
   Add/Update Methods:
   ```java
   - PaymentIntent initiateTopUp(BigDecimal amount) // Creates PaymentIntent and Payment record
   - void creditWallet(Long userId, BigDecimal amount, Long paymentId) // Credits wallet after successful payment
   ```
   
   IMPORTANT: Use database transactions and optimistic locking (via @Version) to prevent race conditions.


PHASE 2: CONTROLLERS AND ENDPOINTS
-----------------------------------

6. **Create WalletController** (or update existing)
   Location: src/main/java/com/example/auctionhub/auctionhub/controller/WalletController.java
   
   Endpoints:
   
   a) POST /api/wallet/topup
      - Request body: { "amount": 50.00 }
      - Validates amount (minimum $1, maximum $10,000)
      - Creates Stripe PaymentIntent
      - Returns client secret to frontend
      - Response: { "clientSecret": "pi_xxx_secret_xxx", "paymentId": 123 }
   
   b) GET /api/wallet
      - Returns current wallet balance and transaction history
      - Response: { "availableBalance": 150.00, "frozenBalance": 0, "totalSpend": 50.00 }

7. **Create StripeWebhookController**
   Location: src/main/java/com/example/auctionhub/auctionhub/controller/StripeWebhookController.java
   
   Endpoint:
   
   POST /api/stripe/webhook
   - Receives Stripe webhook events
   - Verifies signature using webhook secret
   - Delegates event handling to StripeService
   - Returns 200 OK immediately (Stripe requires fast response)
   
   CRITICAL: This endpoint must NOT require authentication (Stripe calls it directly).
   Add to SecurityConfig to permit access.
   
   Handle these events:
   - payment_intent.succeeded (credit wallet)
   - payment_intent.payment_failed (update payment status)
   - payment_intent.canceled (update payment status)

12. **Create Wallet Top-up UI**
    Location: src/main/resources/static/js/wallet.js (new file)
    
    Flow:
    1. User enters amount to add
    2. Frontend calls POST /api/wallet/topup
    3. Receives clientSecret from backend
    4. Initialize Stripe with publishable key
    5. Use Stripe Elements to collect card details
    6. Confirm payment with stripe.confirmCardPayment(clientSecret)
    7. Show success/error message
    8. Redirect to wallet page
    
    Example Code:
    ```javascript
    const stripe = Stripe('pk_test_your_publishable_key');
    
    // Create card element
    const elements = stripe.elements();
    const cardElement = elements.create('card');
    cardElement.mount('#card-element');
    
    // Handle form submission
    async function handleTopup(amount) {
        // Call backend to create PaymentIntent
        const response = await fetch('/api/wallet/topup', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ amount })
        });
        const { clientSecret } = await response.json();
        
        // Confirm payment
        const result = await stripe.confirmCardPayment(clientSecret, {
            payment_method: { card: cardElement }
        });
        
        if (result.error) {
            // Show error
            console.error(result.error.message);
        } else if (result.paymentIntent.status === 'succeeded') {
            // Payment successful
            window.location.href = '/wallet.html?success=true';
        }
    }
    ```


PHASE 5: SECURITY AND VALIDATION
---------------------------------

13. **Security Configuration**
    Location: src/main/java/com/example/auctionhub/auctionhub/config/SecurityConfig.java
    
    Update to allow webhook endpoint:
    ```java
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/stripe/webhook").permitAll() // Allow Stripe webhooks
                .requestMatchers("/api/wallet/topup").authenticated() // Require auth
                // ... other rules
            )
            .csrf(csrf -> csrf
                .ignoringRequestMatchers("/api/stripe/webhook") // Disable CSRF for webhooks
            );
    }
    ```

14. **Input Validation**
    Create DTO for top-up request:
    
    Location: src/main/java/com/example/auctionhub/auctionhub/dto/WalletTopUpRequest.java
    ```java
    @Data
    public class WalletTopUpRequest {
        @NotNull(message = "Amount is required")
        @DecimalMin(value = "1.00", message = "Minimum top-up is $1.00")
        @DecimalMax(value = "10000.00", message = "Maximum top-up is $10,000.00")
        @Digits(integer = 10, fraction = 2)
        private BigDecimal amount;
    }
    ```

IMPORTANT NOTES
===============

Security Considerations:
------------------------
1. NEVER commit Stripe API keys to version control
2. Always verify webhook signatures to prevent fraud
3. Use HTTPS in production (required by Stripe)
4. Webhook endpoint must respond within 5 seconds
5. Do NOT trust frontend for payment confirmation - always use webhooks
6. Implement rate limiting on top-up endpoint
7. Use optimistic locking (@Version) to prevent race conditions on wallet balance

Database Transactions:
----------------------
1. Wrap wallet credit operations in @Transactional
2. Use proper isolation level (READ_COMMITTED or higher)
3. Handle OptimisticLockException for concurrent updates
4. Create Payment record BEFORE creating Stripe PaymentIntent
5. Update Payment status only in webhook handler

Stripe Best Practices:
----------------------
1. Always handle idempotency (check for duplicate PaymentIntents)
2. Store metadata in PaymentIntent (userId, paymentId for tracking)
3. Implement proper error handling for Stripe API calls
4. Use Stripe test mode during development
5. Keep Stripe SDK updated for security patches
6. Log all Stripe API interactions for debugging
7. Process webhooks asynchronously for scalability

Webhook Handling:
-----------------
1. Verify signature using Stripe webhook secret
2. Respond with 200 OK immediately (before processing)
3. Process events asynchronously if needed
4. Handle duplicate events gracefully (check if already processed)
5. Log raw webhook payload for debugging
6. Implement retry logic for failed event processing
7. Monitor webhook delivery in Stripe Dashboard

Amount Handling:
----------------
1. Stripe uses smallest currency unit (cents for USD)
2. Convert BigDecimal to cents: amount.multiply(100).longValue()
3. Validate minimum ($1.00) and maximum ($10,000) amounts
4. Use BigDecimal for all money calculations (never float/double)
5. Store amounts with precision=10, scale=2 in database

Existing Models Integration:

Your existing models:

Add to Payment if missing:

TROUBLESHOOTING
===============

Common Issues:
--------------
1. Webhook not receiving events
   → Use Stripe CLI: stripe listen --forward-to localhost:8080/api/stripe/webhook
   → Check firewall/security groups in production
   → Verify endpoint is publicly accessible

2. Signature verification fails
   → Ensure using correct webhook secret (different for each endpoint)
   → Check if request body is parsed before verification (must use raw body)
   → Verify webhook secret matches Stripe Dashboard configuration

3. Payment succeeded but wallet not credited
   → Check webhook event processing logs
   → Verify payment_intent.succeeded event is enabled
   → Check database transactions are committing
   → Look for exceptions in webhook handler

4. Duplicate top-ups
   → Implement idempotency check using PaymentIntent ID
   → Add unique constraint on stripe_payment_intent_id in database
   → Check for race conditions in wallet update logic

5. Frontend errors
   → Verify Stripe publishable key is correct (pk_test_... or pk_live_...)
   → Check CORS configuration allows Stripe requests
   → Ensure card element is properly mounted before confirmation
